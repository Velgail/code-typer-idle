# Code Typer Idle

日銭を稼ぎ、コードを学び、ゲームを作る。理解度と事業維持費をやりくりする、日本語の無料インクリメンタルゲームです。

クリック、または出題されたコードを正確にタイプして入力します。日銭ワークは資金に、写経は分野別の理解度に、開発は有効コードに変わります。理解不足の開発はエラーや技術的負債になります。自動化も、コードをレビューできなければビルドを壊します。

最初の数当てゲームから、インディー作品、AAA、永続オンライン宇宙へ。AAAの先には世代ごとに要求規模が増す多元宇宙エンジンと、コード資産を引き継ぐ再出発があります。100万行で終了するゲームではありません。

## 起動

公開用ファイルを同梱しているため、遊ぶだけならビルドは不要です。Python 3がある環境なら、リポジトリのルートで実行します。

```sh
python3 -m http.server 4173 --directory docs
```

ブラウザで `http://localhost:4173/` を開きます。`npm run dev` はソースの変更をビルドしてから同じサーバーを起動します。ES Modulesを使うため、HTMLをファイルとして直接開く方法には対応していません。

## GitHub Pages

公開する静的ファイルはすべて `docs/` にあります。リポジトリ名を含むサブパスでも動く相対URLを使っています。

1. この変更を公開対象ブランチ（通常は `main`）にコミットしてpushします。
2. GitHubの **Settings → Pages → Build and deployment** を開きます。
3. **Source: Deploy from a branch** を選びます。
4. 公開するブランチと **`/docs`** を選んで保存します。

このリポジトリの公開先は、設定後に `https://velgail.github.io/code-typer-idle/` となる想定です。実際の公開状態とURLはGitHubのPages画面で確認してください。

`docs/.nojekyll` を同梱しています。外部CDN、広告、課金、API、バックエンド、アクセス解析は使いません。プレイデータはブラウザ内に保存します。

## 操作と進行

| 操作 | 内容 |
| --- | --- |
| クリック | 現在の作業に1入力 |
| コードタイピング | 事務は原票からCSV化、学習・開発は出題コードを入力。完入力で追加報酬 |
| 言語選択 | C++ / C# / Rust / Go / Python / Java / SQL / Lua |
| 作業タブ | 日銭 / 学習 / 開発の切替。数字キーでタブは切り替わりません |
| Esc | コード入力欄からフォーカスを外す |
| 学習分野ボタン | 文法、設計、描画、基盤から選択。分野ごとの教材が必要 |
| リファクタリング | 必要理解度100%で技術的負債を修復 |
| ビルドして公開 | 進捗100%、ビルド正常、負債10%以下で公開 |
| 自動開発スイッチ | 開発ユニットだけを停止・再開。マクロは稼働を継続。研究は教材が必要 |
| ロードマップ | 今後の企画と、資産を引き継ぐ再出発 |
| 設定 | 打鍵音、演出削減、一時停止、セーブの書き出し・読み込み |

入力欄はクリック方式でも表示し、欄をクリックするとそのままタイピングを始められます。誤入力も文字として表示し、Backspaceや削除で修正できます。正しい部分だけを進捗と報酬に計上し、削除して打ち直した同じ文字は重複計上しません。貼り付け、ドロップ、キー長押しは数えません。コード入力中のTabは空白4文字を入力し、報酬と入力回数は1打鍵分として計上します。Shift+TabまたはEscで入力欄を離れられます。伝票入力ではTabを通常のフォーカス移動として使います。IMEの変換中は未確定文字を保持し、確定後に判定します。全角英数字は半角に、事務入力の英字は大文字に整えます。コードの大文字・小文字は区別します。モバイルでもクリックと画面キーボードを使えます。作業タブ、学習分野、伝票画像をクリックした後は、学習可能な状態ならタイピング欄へフォーカスを戻します。

出題は8言語×4分野×4種類のコード例×16通りのデータ差分で、計2,048問を同梱。コードの断片を使うため、周辺の宣言やライブラリの読み込みを省略した例もあります。出題コードを実行することはありません。正解文字でクリックの1.5倍、誤入力なしの完入力でコードは合計2倍、原票入力は合計2.25倍の作業量を得ます。原票は読み取りと整形の時間を見込み、完入力ボーナスを厚くしています。誤入力は完入力ボーナスを減らします。

日銭ワークは伝票画像のデータ化という事務作業です。原票の画像を読み、伝票番号・日付・品名・数量・単価をCSVへ整えます。日付はYYYY-MM-DD、金額は記号や桁区切りを除きます。完成済みの入力文字列は画面に出さず、原票と入力仕様を示します。プログラミング知識は増えません。画像原票256種類を同梱。日付は同日に複数件発行される営業日の並び、品目と数量は別々の固定乱数で選び、品目ごとの価格と少量の数量値引きを使います。数量の単位も本・冊・台・箱など品物に合わせます。再読込や端末間のセーブ移動でも原票は同じです。更新前の入力途中の原票は、その1問を終えてから新版に切り替えます。OCR・入力マクロで読み取りと入力を自動化できます。学習とゲーム開発では、引き続き8言語のコードを出題します。

初期資金は¥100。日銭ワークは100作業量ごとに1件を納品し、初期報酬は1件¥100です。1クリック＝1作業量で、未完成の仕事は現金になりません。作業を切り替えても途中進捗は保存され、着手時の単価で精算します。マクロも同じ納品処理を使います。¥1,500のマクロと同額の基礎教本を、受託の収益で購入します。

## 事業維持費

ゲーム内1日＝実時間1時間。序盤は家族の支援を受けて実家で制作し、個人の生活費は会計の対象外です。商用条件を満たした発売に応じて独立・事業拡大し、費用が増えます。無料公開だけでは費用段階は上がりません。

| 段階 | 移行条件 | 維持費 / 日 | 事務所代 / 30日 | 費用の内容 |
| --- | --- | ---: | ---: | --- |
| 実家で個人制作 | 開始時 | ¥600 | ¥0 | 電力・通信・消耗品 |
| 個人事業として独立 | ブロック崩しを有料発売 | ¥1,500 | ¥60,000 | 開発サービス・検証機材・通信 |
| 小規模チーム | ローグライクを有料発売 | ¥12,000 | ¥180,000 | 外注・保守・開発環境 |
| 開発スタジオ | 3D作品を有料発売 | ¥100,000 | ¥600,000 | 人件費・制作環境・運営 |
| 大規模開発事業 | AAAを有料発売 | ¥1,000,000 | ¥3,000,000 | 大規模チーム・サーバー・運営 |

維持費は日次精算。事務所代は発生分を所持金から別枠に積み立て、30日ごとに精算します。途中で事業を拡大した場合は、その規模で過ごした時間分だけを請求します。積立は所持金から差し引くため、月末の二重払いはありません。不足分は全額赤字に残り、手動効率が50%になります。旧版の−¥1,200の打ち止めによる費用消失は廃止しました。

「固定費の見直し」で日々の維持費を25%削減します。事務所代には適用しません。旧セーブの自炊セットも同じ設備IDで引き継ぎます。最初のマクロは0.25作業量/秒。初期の平均維持費約¥0.167/秒を少し上回る収入で、設備を次々に買える速さにはなりません。

教材を持っていない分野は、クリック・コードタイピング・研究ラボのいずれでも学習できません。教材未購入時はコード表示と入力を止め、必要な本の名前・価格とショップへの案内を表示します。最初の基礎教本は¥1,500です。各分野の教材購入後、学習量は教材1レベルごとに+100%、モニターは+25%。キーボードの手動入力は+25%、IDEの完全理解時の手動開発は+35%ずつ増えます。各設備内では加算です。理解度が高くなるほど、次の1ポイントに必要な学習量も増えます。

数当てゲームの売上はゼロです。完成すると理解度が増え、高単価ワークと開発設備を解禁できます。有料作品は品質60以上かつ必要理解度100%以上で販売され、初回売上と継続売上が入ります。新作公開後は自動開発を停止するので、次の要求理解度を確認してから再開してください。

## 到達時間の目安

新規セーブ・周回なしで、初回AAAまで放置込み3〜7日を基準に調整しています。ゲーム内の開発ロードマップにも同じ表を表示します。

| 到達点 | クリック8回/秒・連続 | タイピング300打鍵/分・連続 | クリック8回/秒・離席あり |
| --- | ---: | ---: | ---: |
| 基礎教本 | 約7分 | 約5.3分 | 約7分 |
| 最初の無料作品 | 約28分 | 約21.5分 | 約28分 |
| 最初の有料作品 | 約2.1時間 | 約1.7時間 | 約10時間 |
| インディー作品 | 約8.5時間 | 約7.2時間 | 約38時間 |
| スタジオ規模の3D作品 | 約36時間 | 約33.4時間 | 約78時間 |
| AAA | 約117.9時間 | 約113.9時間 | 約168時間 |

タイピング列は300打鍵/分（5打鍵/秒）を基準に、全問正解と完入力ボーナス込みで計算します。誤入力や問題の読み取り時間によって実際の到達は遅くなります。30打鍵/秒は別のストレステストに残しています。「離席あり」は最初に1時間、その後は日中16時間の活動帯に2時間ごと5分操作し、夜は8時間離席。AAAまでの実操作時間は約5.6時間です。購入順や周回によっても変わり、最速手順を保証する数字ではありません。

計測では資源を注入せず、日次精算の見込額を残して購入します。全条件で途中の所持金も赤字にならないことを検証します。手順は `scripts/simulate-balance.mjs` に記載。`npm run balance` で再計測でき、`npm run balance -- --write` でゲーム内の表を更新します。

## セーブ

- 5秒ごと、タブを隠したとき、ページを離れたときに `localStorage` へ保存。
- 直前の保存内容をバックアップ。メインデータの破損時は復旧を試みます。
- 設定からJSON形式で書き出し・読み込み。読み込みは現在の進行を置き換えます。
- 離席中は最大8時間分の自動処理と事業維持費を計算。購入や公開は手動です。
- Web Locks対応ブラウザでは、同じオリジンの別タブからの上書きを防止します。
- プライベートブラウズ、容量制限、ブラウザデータの削除に備えて、定期的な書き出しをおすすめします。

保存先のキーは `code-typer-idle:save:v1`。複数のGitHub Pagesプロジェクトは同じドメインを共有するため、他作品と衝突しない名前にしています。サーバーへのデータ送信はありません。

バランスv4でも旧セーブの資金、理解度、設備、公開作品、資産を引き継ぎます。旧暦の日付と1日の経過割合も維持。新制度の費用は更新後の経過時間から計上し、過去の費用や事務所代をさかのぼって請求しません。旧セーブは上の到達時間の目安には含みません。

## バージョン更新とキャッシュ

公開用JavaScriptとCSSは内容に応じたファイル名で生成し、すべてのモジュール参照を同じビルドへ揃えます。新旧ファイルが混在する更新を防ぎ、以前の配信ファイルも残します。

起動時・タブへ戻ったとき・60秒ごとに `version.json` をキャッシュなしで確認します。更新があれば「保存して更新」を表示し、保存成功後に新しいURLで再読み込みします。保存失敗や別タブ起動時は更新を止め、セーブを保護します。通信できないときはプレイを継続します。更新のためにlocalStorageやブラウザデータを削除する必要はありません。

指紋付き配信より前のHTMLには、旧URL `js/app.js` から最新版へ移る入口を残しています。すでに開いている旧版には更新検知処理がないため、初回はページを開き直します。旧版の全ファイルが強くキャッシュされて開き続ける場合は、[更新用URL](https://velgail.github.io/code-typer-idle/?v=1.2.0)を一度開いてください。以降はゲーム内で更新を検知します。

## 開発と検証

```text
src/
  core.js           DOMに依存しないゲームルールと保存形式
  app.js            入力、画面更新、音、保存、ブラウザ連携
  typing.js         多言語の出題と正誤判定
  office.js         伝票画像・入力仕様・事務用の256問
  pacing.js         シミュレーションから生成する到達時間
  updates.js        更新検知と保存後の再読み込み
docs/
  index.html        画面とダイアログ
  style.css         UIのスタイル元
  build/            指紋付きの公開用JavaScript・CSS
  version.json      配信中のバージョン情報
  assets/           同梱アイコン
  js/               旧キャッシュからの移行入口・旧版の依存ファイル
scripts/
  build.mjs         依存なしで配信用ファイルを生成
  simulate-balance.mjs  入力速度と離席条件別の進行計測
tests/
  core.test.js      ゲームルール・会計・旧セーブ移行
  typing.test.js    出題2,048問、正誤、報酬、保存
  balance.test.js   3〜7日の進行と高速入力条件の回帰検証
  browser.mjs       Chromiumの操作・表示・キャッシュ更新検証
DESIGN.md           数式と企画からの具体化
```

Node.js 22以降でルールのテストを実行できます。外部パッケージは不要です。

```sh
npm run build
npm test
```

ソースを変更したら `npm run build` を実行し、`docs/` の生成物もコミットしてください。CIは再ビルドとの差分がないことを確認し、ルールとChromiumのブラウザ検証を実行します。バランス変更時は先に `npm run balance -- --write` を実行します。

ブラウザテストだけはPlaywrightが必要です。

```sh
npm install --no-save playwright
npx playwright install chromium
npm run test:browser
```

ブラウザテストは自身でローカルサーバーを起動し、終了時に停止します。既存サーバーを使う場合は `CTI_TEST_URL`、Chromiumの実行パスを指定する場合は `CHROMIUM_PATH` を設定できます。スクリーンショットはGit管理外の `work/` に出力します。

ルール・会計・出題・進行の39件をテストします。ブラウザテストでは実際の入力欄クリック、正しいコード入力、IME変換・確定・取消、誤入力の表示と編集、重複報酬防止、貼り付けとキー長押しの拒否、8言語、セーブ復帰、公開、作品一覧、到達時間表、設定、書き出し・読み込み、別タブ制御を検証。キャッシュ更新は長期キャッシュした旧HTML・モジュール・バージョン情報を残し、別バージョンへの配信切替、保存失敗時の停止、セーブ維持、オフライン継続を実ブラウザで確認します。数字入力がタブを変えないこと、入力フォーカスの復帰、教材の未購入・購入直後・分野切替・再読み込みも確認します。画面幅1440 / 1024 / 768 / 390 / 360pxでも表示を確認します。シミュレーションは購入方針を固定した比較で、実プレイ全体の保証ではありません。
